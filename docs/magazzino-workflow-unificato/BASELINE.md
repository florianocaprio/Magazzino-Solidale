## Architettura e contratti condivisi

- Monorepo `pnpm`: frontend React/Vite in `artifacts/magazzino-solidale`, API Express in `artifacts/api-server`, schema Drizzle e runner migrazioni in `lib/db`.
- Contratto sorgente in `lib/api-spec/openapi.yaml`; client React e validatori generati in `lib/api-client-react/src/generated` e `lib/api-zod/src/generated`. Il comando di rigenerazione è `pnpm --filter @workspace/api-spec run codegen`.
- Autenticazione a sessione e autorizzazioni backend in `artifacts/api-server/src/middlewares/auth.ts` e nel montaggio delle route. Nascondere menu o pulsanti non costituisce un controllo di sicurezza.
- Scoping territoriale comune in `artifacts/api-server/src/lib/centroScope.ts`: Centro di Ascolto e Area operativa sono filtri additivi. Il catalogo prodotti è intenzionalmente globale.
- Inventario senza tabella saldi: la giacenza deriva da `lotti.quantita_residua`. `movimenti` è il giornale append-only; `POST /movimenti` risponde 405 e rinvia ai servizi di dominio.
- Precisione numerica centralizzata in `inventoryDecimal.ts` e `inventoryQuantityDimensions.ts`; le quantità sono `numeric(14,6)` e i fattori `numeric(18,9)`.

## Difetti e rischi preesistenti

1. **Audit legacy incompleto (M1C/M2):** 35 movimenti su 37 non hanno `operatore_id`. Devono restare “Non disponibile — dato precedente”; non vanno attribuiti all'utente della migrazione.
2. **Test API non isolati per default (M0):** `vitest.config.ts` serializza i file ma usa direttamente `DATABASE_URL`. Un comando privo di URL esplicita può colpire un DB operativo.
3. **Fresh gate avvia processi dell'API (M0):** oltre allo smoke CRUD, `src/index.ts` registra il job di downgrade priorità e abilita il geocoding pubblico salvo override. Sul fresh DB sintetico non ha prodotto effetti esterni; sulla copia popolata non va eseguito così.
4. **Giacenze senza Area scelta (M1B):** lo scope autorizzativo limita il chiamante, ma un utente globale può ottenere il totale di tutti i magazzini omettendo il filtro.
5. **Soglia minima aggregata ambigua (M1B/M2):** `prodotti.scorta_minima` è globale ma applicata a ogni riga prodotto/magazzino; sommarla o moltiplicarla nell'area non è giustificato dal modello.
6. **Supporto import incompleto (M3B):** il contratto e la route accettano solo XLSX, non XLS/CSV.
7. **Due code materiali (M5):** preparazione da bolla e materiali dell'intervento hanno modelli e UI distinti.
8. **Audit frammentato (M1C):** alcune cronologie sono verticali, alcune best-effort, altre coincidenti col giornale inventariale; nessuna copertura completa delle mutazioni è dimostrata.
9. **Build root dipendente da ambiente (baseline):** `mockup-sandbox/vite.config.ts` richiede sia `PORT` sia `BASE_PATH`; il comando nudo fallisce, mentre la configurazione usata dai Dockerfile passa.
10. **Avvisi PostgreSQL nei test (baseline):** più test emettono la deprecazione `client.query()` durante una query già attiva, destinata a diventare errore con `pg@9`; la suite resta verde ma il debito va censito prima di un upgrade.
11. **Warning frontend non bloccanti (baseline):** Vite segnala sourcemap non risolvibili per alcuni componenti UI e chunk superiori alla soglia informativa; il controllo bundle dedicato passa.
12. **Collisione con porte effimere nei test (baseline):** pubblicare container sui port host `58080`/`58082` può intercettare le porte casuali aperte da Supertest. Per le suite API usare porte loopback fuori dalla gamma effimera del sistema oppure arrestare i container applicativi.
