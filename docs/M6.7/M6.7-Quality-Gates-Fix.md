## Piano di correzione

1. Inventario deterministico ed esaustivo: ogni file API assegnato una sola volta al gruppo compatibile; ogni spec browser eseguito separatamente sul proprio database, nelle cinque viewport esistenti. File nuovi o guardie non coperte devono fermare il launcher anziché essere esclusi.
2. Provisioning PostgreSQL16 nominativo, in tmpfs, senza volumi persistenti. Verifica di ID container, label, porta loopback, rete, mount, versione server, DB e schema vuoto prima di abilitare i soli flag pertinenti. Nessuna connessione ricevuta dall'ambiente operativo.
3. Bootstrap schema corrente e runner canonico, ledger/checksum/replay; seed soltanto sintetico e attivazione login tramite percorso canonico. Lock del launcher e singolo worker; niente sovrapposizione API/browser sullo stesso ambiente mutante. Cleanup nominativo in `finally` anche in caso di failure.
4. Preservare il job static/frontend/Docker già verde. Introdurre orchestrazione riproducibile per i job API/browser; niente nuovi skip o retry. Distinguere gli skip storici di campioni esterni e quelli limitati intenzionalmente a certe viewport.
5. Riproduzioni mirate, intere suite locali, controlli frontend/typecheck/build Docker/budget; soltanto dopo validazione completa, commit/push normale su main e verifica del run GitHub risultante.
