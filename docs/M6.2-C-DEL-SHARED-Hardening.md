## Nuova evidenza: collisione delle famiglie IP

La successiva partizione API guarded ha **121 PASS / 1 FAIL / 0 SKIP**.
Nuovo FAIL in `mensa.test.ts`: «applica al riepilogo gli scope area operativa,
Centro di Ascolto e zona UDS», ancora `socket hang up`. File invariato;
il suo `makeApp()` usa Supertest con listener implicito, diverso dal percorso
Mensa con sessione reale già dotato di listener espliciti. Il FAIL è conservato
in `H/formal-guarded.json`, non riclassificato come PASS.

L'ispezione delle dipendenze installate individua una discrepanza concreta:
Supertest 7.2.2 chiama `app.listen(0)` senza host, ma `serverAddress()` restituisce
sempre `http://127.0.0.1:<porta>`. Sul Mac il listener è IPv6 (`::`).
Superagent 10.3.0 imposta `agent: false`: non vi è prova di una connessione
keep-alive riutilizzata; questa ipotesi non è adottata.

Due riproduzioni controllate, indipendenti dalle regole applicative:

1. `H/bind-diagnostic.json`: listener Node `::` sulla stessa porta 58461 del
   PG Docker **disposable del task**, bound IPv4. GET su `::1` → 200 dal
   listener atteso; GET su `127.0.0.1` → ECONNRESET / socket hang up.
2. `H/supertest-collision.json`: due server HTTP sintetici, IPv4 e IPv6, stesso
   numero di porta. `request(serverIPv6)` costruisce URL IPv4 e raggiunge il
   server errato: prima 404 `WRONG_LISTENER`, poi ECONNRESET se quel server
   chiude il socket. **Zero richieste al server atteso**, due a quello errato.
   Nessun DB usato in questa seconda riproduzione.

È quindi dimostrato un difetto di indirizzamento dell'harness: la porta non
identifica da sola il listener quando le famiglie IP differiscono. Può spiegare
sia falsi 404 sia reset intermittenti durante molte aperture di porte effimere.
Non si afferma retroattivamente quale porta fosse stata scelta nei vecchi FAIL,
che non hanno trace sufficienti. Nessuna regressione contabile dimostrata.

Il fix locale DEL-SHARED previene questa classe di collisione perché il suo
helper ascolta esplicitamente su 127.0.0.1. La prima campagna di questo mandato,
completata anche per la partizione indipendente, conserva l'esito **FAIL**:
1711 PASS / 1 FAIL / 4 SKIP, 137 file. La parte non guarded è 1590 PASS / 4 SKIP;
DEL-SHARED e gli altri 35 M4B.2 passano anche qui. Nessun rilancio identico per
far sparire il FAIL Mensa: prima è stata isolata la causa comune sopra.
