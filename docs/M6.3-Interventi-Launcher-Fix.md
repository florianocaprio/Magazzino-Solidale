## Correzioni

### 1. Identità esatta dei gruppi browser

La precedente normalizzazione rimuoveva i numeri finali, trasformando `m63`, `m5`, `m5c1`, `m4` in nomi inesistenti. `resolveBrowserGroup()` ora usa una mappa esplicita e lookup esatto, senza rimozione di cifre né alias impliciti. Gruppi sconosciuti vengono rifiutati prima del setup. Ogni chiamata restituisce una copia della configurazione, impedendo contaminazioni fra gruppi.

Gruppi previsti: `m63`, `m5`, `m5c1`, `m4`, `mensa`, `emporio`; `consegne` disponibile per verifica mirata. I suffissi preparatori ambigui come `consegne4` sono esplicitamente rifiutati: il nome dell'evidenza non deve modificare l'identità del gruppo.

### 2. Esclusione reciproca e rinomina sicura

`withExclusiveTestEnvironment()` acquisisce un file con creazione atomica `wx`, permessi 0600, PID, contesto e token di proprietà. Il launcher corretto usa per tutte le operazioni lo stesso lock `/private/tmp/magazzino-m63-test-ports.lock`, condiviso fra processi e cartelle evidenze che utilizzano queste porte.

Il lock copre tutta la vita del comando API/browser, non soltanto bootstrap o query: finché la suite API non termina, il browser non può partire né rinominare il DB, anche negli intervalli in cui PostgreSQL non vede connessioni. Non ci sono polling/retry automatici per ottenere il verde. Una seconda esecuzione viene rifiutata subito. Il rilascio verifica il token ed è effettuato in `finally` dopo la conclusione del comando. Dopo un crash il lock resta bloccante: non viene eliminato automaticamente presumendo che l'ambiente sia libero.

Seconda difesa: `renameIdleTestDatabase()` ammette solo le tre sorgenti disposable previste e destinazioni `m63_*`; verifica `pg_stat_activity`, poi lascia anche a PostgreSQL la verifica atomica di `ALTER DATABASE`. Nessuna terminazione forzata di client, nessuna disabilitazione di vincoli. Il chiamante mantiene i controlli Docker preesistenti su nome, label, porte e mount prima dell'accesso SQL.

La suite completa API viene eseguita fino al termine, poi i sei gruppi browser uno alla volta. Solo successivamente Emporio conserva il DB API con un nome distinto e crea il proprio fresh `m62a`, richiesto dal guardrail canonico.
